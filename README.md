# Aurum Drive: Premium Car Rental Platform

A complete full-stack car rental website: **Next.js 16 + React 19 + TypeScript + Tailwind CSS + Framer Motion + Lucide icons** on the front, **Next.js API routes** on the back, and **Supabase** (PostgreSQL, Auth, Storage) for data, login and image uploads.

- Customers: register, log in, reset password, browse and filter cars, book, manage and cancel bookings, edit profile and avatar, review completed rentals.
- Admins: separate sign-in, dashboard with KPIs and charts, vehicle CRUD with image upload, booking approval/rejection/completion, customer management, revenue and CSV export, homepage content management.
- Security: Row Level Security on every table, server-side role checks, prices computed by the database, and a database-level **double-booking guard**. The Supabase *service role* key is **never** used.

> Brand name, contact details, currency and pickup locations are in `src/lib/config.ts` (look for `EDIT HERE`).

## What was verified, and what was not

Verified before delivery:
- `npm run build` (production build) and `tsc --noEmit` pass with no errors.
- All SQL migrations plus `seed.sql` ran without errors on a real PostgreSQL 16 server (with minimal stand-ins for Supabase's `auth`/`storage` schemas).
- Database rules were exercised with test users: customers cannot promote themselves to admin; forged prices/status on insert are overwritten; overlapping bookings are rejected while back-to-back bookings are accepted; customers only see their own bookings; customers cannot edit cars or read the newsletter list; anonymous visitors cannot read bookings.
- Route protection on the running production server: `/dashboard`, `/booking`, `/admin/*` redirect to login when signed out; `/api/admin/*` return 401; input validation errors return 400.

**Not** verified (needs your live Supabase project): real sign-up/login, email delivery (confirmation and password reset), Storage uploads, and a full click-through of the admin and booking flows against live data. Follow Step 6 to test these yourself. The first run is the real test, so please report anything that behaves differently.

Limitations to know about:
- **No online payment.** Bookings are "pay at pickup". A `payments` row is created per booking and marked `paid` when you mark the booking Completed. Adding Stripe is a natural next step.
- **Car images are original illustrations** (SVG files in `public/images/cars/`, generated by `npm run gen:images`) so there are never broken links. Replace them with real photos via Admin > Vehicles > Upload (see Step 6.5).
- Customer review names are shown as "Verified customer" (Row Level Security hides other customers' profiles).
- Fonts are system font stacks (no network needed). To use Google Fonts, see `tailwind.config.ts`.

## STEP 1: Prerequisites

1. **Node.js (LTS, version 20 or newer)**: download from https://nodejs.org and run the installer.
2. **VS Code** (editor): https://code.visualstudio.com
3. **Git**: https://git-scm.com/downloads (accept the defaults).
4. Check everything in a terminal (on Windows use *PowerShell*, on Mac use *Terminal*):
   ```bash
   node -v    # should print v20.x or higher
   npm -v     # prints a version number
   git --version
   ```

## STEP 2: Extract the ZIP and open it

1. Right-click `Premium-Car-Rental-Platform.zip` and choose **Extract All** (Mac: double-click).
2. Open VS Code, then **File > Open Folder** and select the extracted `car-rental-platform` folder.
3. Open the built-in terminal: **Terminal > New Terminal**.

## STEP 3: Install dependencies

In the VS Code terminal:
```bash
npm install
```
This downloads everything the project needs (a minute or two). It creates a `node_modules` folder; that is normal.

## STEP 4: Set up Supabase

1. Go to https://supabase.com and click **Start your project**. Sign up (GitHub or email).
2. Click **New project**. Choose a name (e.g. `car-rental`), set a strong **Database Password** (save it somewhere), pick the region closest to you, and click **Create new project**. Wait about two minutes. (Supabase creates the PostgreSQL database for you.)
3. **Find your keys:** left sidebar > **Project Settings** (gear icon) > **API** (or "API Keys").
   - **Project URL**: looks like `https://abcdxyz.supabase.co`
   - **anon / publishable key**: the long key labelled `anon` or `publishable`. *Do not use the `service_role` / `secret` key.*
4. **Create your environment file.** In VS Code, duplicate `.env.example` and name the copy `.env.local`. Fill it in:
   ```
   NEXT_PUBLIC_SUPABASE_URL=https://abcdxyz.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-or-publishable-key
   NEXT_PUBLIC_SITE_URL=http://localhost:3000
   NEXT_PUBLIC_CURRENCY=USD
   ```
   `.env.local` is git-ignored, so your keys are never uploaded.
5. **Run the database migrations.** In Supabase: left sidebar > **SQL Editor** > **New query**.
   - Easiest: open `supabase/setup_all.sql` in VS Code, copy everything, paste into the SQL Editor, click **Run**. You should see "Success. No rows returned".
   - Or run the four files in `supabase/migrations/` one by one, in order: `001_schema.sql`, `002_functions_triggers.sql`, `003_rls_policies.sql`, `004_storage.sql`.
6. **Load sample data.** New query, paste `supabase/seed.sql`, click **Run**. This adds 12 vehicles, 4 testimonials and 1 promotional banner. Run it only once.
7. **Storage buckets.** Migration `004_storage.sql` already creates two public buckets, `car-images` (admin uploads) and `avatars` (customers' own pictures), with their policies. Verify at **Storage** in the sidebar: both should be listed. If a bucket is missing, click **New bucket**, use the exact name, tick **Public bucket**, then re-run `004_storage.sql` to add the policies.
8. **Authentication settings** (left sidebar > **Authentication**):
   - **Sign In / Providers > Email**: enabled. For quick local testing you may switch **Confirm email** off, so new accounts can log in immediately. For production, leave it on.
   - **URL Configuration**: set **Site URL** to `http://localhost:3000` for now (you will add your Vercel address in Step 7).

## STEP 5: Create the first admin account

Nobody can register as an admin from the website. Admin rights are assigned in the database:

1. Start the site (Step 6) and **register a normal account** at `/register` with the email you want to use as admin.
2. In Supabase > **SQL Editor**, run (use your email):
   ```sql
   update public.profiles set role = 'admin' where email = 'you@example.com';
   ```
3. Open `http://localhost:3000/admin/login` and sign in with that account. You land on the admin dashboard.

To add more admins later, repeat the SQL for their (already registered) email. To remove admin rights, set `role = 'customer'`.

## STEP 6: Run locally and test

```bash
npm run dev
```
Open http://localhost:3000. (If you see a "connect Supabase" screen, re-check `.env.local` and restart with Ctrl+C then `npm run dev`.)

Test checklist:
1. **Register** at `/register`, then log out and **log in** at `/login`. Try **Forgot password** (needs email delivery; Supabase's built-in email is rate-limited, which is fine for testing).
2. **Search**: on the home page choose dates and click *Search cars*. Use filters and sorting on `/cars`.
3. **Book**: open a car, choose dates, *Continue to booking*, fill details, *Review*, *Submit*. Your dashboard (`/dashboard`) shows it as **Pending**.
4. **Double-booking check**: try to book the same car for overlapping dates (from another account or after step 3). The server refuses it.
5. **Admin**: sign in at `/admin/login`.
   - *Bookings*: Approve (Pending to Confirmed), then Complete. Revenue appears on Overview and Revenue.
   - *Vehicles*: add a vehicle, **upload photos** (JPG/PNG/WebP up to 5 MB), edit price, switch availability, delete.
   - *Website*: choose featured cars, edit the promo banner, manage testimonials.
   - *Revenue*: download a CSV.
6. **Customer extras**: edit profile and avatar; cancel a pending booking; request cancellation of a confirmed one; after a booking is Completed, leave a review on the car page.
7. **Access control**: while logged in as a customer, visit `/admin`. You are sent to your dashboard.

## STEP 7: Deploy online (GitHub + Vercel)

1. **GitHub repository**: create an account at https://github.com, click **New repository** (e.g. `car-rental-platform`, keep it Private), do *not* add a README.
2. In the VS Code terminal:
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/YOUR-USERNAME/car-rental-platform.git
   git push -u origin main
   ```
   (`.env.local` is excluded by `.gitignore`. Confirm it is not on GitHub.)
3. **Vercel**: sign in at https://vercel.com with GitHub, click **Add New > Project**, import the repository. Framework preset: **Next.js** (auto-detected).
4. Open **Environment Variables** and add (same names as `.env.local`):
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `NEXT_PUBLIC_SITE_URL` = your Vercel URL, e.g. `https://car-rental-platform.vercel.app` (you can edit it after the first deploy, then redeploy)
   - `NEXT_PUBLIC_CURRENCY`
5. Click **Deploy**. After a minute you get a live URL.
6. **Tell Supabase about your live URL**: Supabase > **Authentication > URL Configuration**:
   - **Site URL**: your Vercel URL
   - **Redirect URLs**: add `https://YOUR-APP.vercel.app/**` and `http://localhost:3000/**`
7. Redeploy once if you changed `NEXT_PUBLIC_SITE_URL` (Vercel > Deployments > Redeploy).
8. **Test the live site** with the Step 6 checklist (especially registration email, password reset and image upload). For production, enable **Confirm email** and consider custom SMTP (Supabase > Authentication > SMTP) because the built-in sender is limited.

## STEP 8: Troubleshooting

| Problem | What to check |
|---|---|
| "Connect Supabase" screen / missing env | `.env.local` exists in the project root, has both keys filled in (no `YOUR-...` placeholders), and you restarted `npm run dev`. On Vercel: variables added, then redeployed. |
| Database connection errors, empty pages | Project URL typo; Supabase project paused (free projects pause after inactivity: click *Restore*); migrations or seed not run. |
| "Incorrect email or password" | Typo, or **Confirm email** is on and the account is unconfirmed. Confirm it via the email link, or switch confirmation off for local tests. |
| Registration says "check your inbox" but nothing arrives | Check spam; Supabase's default email has low hourly limits; set custom SMTP. |
| Password reset link says invalid/expired | Links are single-use and expire. Check **Redirect URLs** include your site (`/**`), and `NEXT_PUBLIC_SITE_URL` matches the address you use. |
| Admin login says "does not have administrator access" | Run the SQL in Step 5 with the exact email, then try again. |
| Image upload fails | Buckets `car-images` / `avatars` must exist and be public; re-run `004_storage.sql`; you must be signed in as admin for car images; files must be JPG/PNG/WebP/AVIF and under 5 MB (avatars 2 MB). |
| "new row violates row-level security policy" / permission denied | Migration `003_rls_policies.sql` (or `004`) was not fully run; re-run `setup_all.sql` (it is safe to re-run). Also make sure you are signed in with the right account. |
| "This vehicle was just booked..." | Working as intended: the dates overlap another booking (pending or confirmed). |
| `npm install` fails | Update Node.js to v20+; delete `node_modules` and `package-lock.json`, run `npm install` again. |
| Build fails on Vercel | Open the build log. Most often a missing environment variable, or a TypeScript error from a code edit. Run `npm run build` locally to reproduce. |
| Port 3000 already in use | `npm run dev -- -p 3001` (then use `http://localhost:3001`, and update the Supabase redirect URL and `NEXT_PUBLIC_SITE_URL`). |

## How the security works (short version)

- **Roles live in the database** (`profiles.role`). The browser never decides who is an admin. Signing up always produces a `customer`; a trigger blocks any attempt to change one's own role.
- **Three layers on admin features**: (1) `proxy.ts` blocks unauthenticated/non-admin requests, (2) each admin page calls `requireAdmin()` and each admin API route calls `apiAdmin()`, (3) Postgres RLS policies call `is_admin()`, so even a direct API call with a customer token is refused.
- **Prices and totals are computed in the database** (`bookings_before_insert` trigger) from the car's current price; the browser only sends car, dates, times and location.
- **Double-booking prevention**: the API checks availability, and a PostgreSQL *exclusion constraint* (`bookings_no_overlap`) guarantees no two pending/confirmed bookings of one car can overlap even under simultaneous requests.
- Customers can only cancel their own *pending* bookings or request cancellation of confirmed ones (trigger-enforced). Admins control status changes.
- Secrets: only the public anon key is used; no service role key exists anywhere in the project.
